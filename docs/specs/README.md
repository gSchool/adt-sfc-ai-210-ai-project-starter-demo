# docs/specs/

**Deliberately empty.**

Specifications detailed enough that an agent can build from them without filling gaps by
guessing: structured requirements, acceptance criteria, architecture decisions, and the
non-goals that stop an agent building what you did not ask for.

That practice comes later. **The directory exists now so adopting it means filling a slot
rather than reorganizing the repository.**

A short task does not need this. A task an agent will run repeatedly, or one where "it
looked right" is not good enough, does.

Some teams call this `resources/` or `rules/`. The name matters less than `AGENTS.md`
pointing at it.
